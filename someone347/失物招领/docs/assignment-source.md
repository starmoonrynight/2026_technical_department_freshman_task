# 招新小任务：校园失物招领系统
相信大家在校园里都遇到过类似的问题：
“我的校园卡不知道丢哪了。”
“在图书馆捡到了一副耳机，应该怎么找到失主？”
“有人捡到了我的东西，但是我不知道去哪里找。”
于是你想：
**为什么不能做一个属于杭电自己的失物招领平台？**
这就是你这次需要完成的项目。
---
# 什么是校园失物招领系统？
简单来说，这是一个帮助同学：
**发布失物信息、寻找失物、发布招领信息，并最终联系失主/拾主的平台。**
例如：
小明丢失了一张校园卡。
他可以登录系统，然后发布：
```
物品：校园卡
地点：下沙校区图书馆
时间：2026-09-26 14:30
描述：黑色卡套，里面有校园卡
```
另一位同学捡到了这张校园卡，也可以发布：
```
物品：校园卡
地点：图书馆二楼
时间：2026-09-26 15:00
描述：捡到一张校园卡
```

# 基础要求
下面的功能是对 0 基础同学的基本要求。
不需要把它当成考试题。
如果你是第一次做开发，先把这些功能做出来就已经很好了（选择产品设计赛道的同学只需要提交PRD+设计稿即可，不要求真正实现这些功能）
## 用户注册和登录
每个用户都应该拥有自己的账号。
至少需要实现：
- 用户注册
- 用户登录
- 获取当前用户信息
- 用户退出登录
你可以自己思考：
用户登录之后，系统怎么知道“现在操作的人是谁”？
可以尝试学习：
- Cookie / Session
- JWT
- Token
不要求一开始就全部理解，可以边做边学。
---
## 发布失物 / 招领信息
用户可以发布自己的信息。
至少支持：
- 创建信息
- 查看信息
- 修改自己的信息
- 删除自己的信息
---
## 查看和搜索
用户应该能够查看其他人发布的信息。
尝试学习数据库中的：
- WHERE
- LIKE
- ORDER BY
- LIMIT
- OFFSET
---
## 状态管理
一个失物信息不应该永远处于“寻找中”。
例如：
```
寻找中
   ↓
已找到
   ↓
已结束
```
用户找到自己的东西之后，可以将对应信息标记为：
**已找到**
这样其他用户就知道这条信息已经不再需要帮助。
---
# 进阶方向
完成基础功能之后，可以尝试给你的失物招领系统增加一些扩展功能。
这里不规定你必须怎么做，只是给你一些思路。
- 图片上传：允许用户上传失物图片
- AI 智能匹配：智能判断平台某失物帖和某招领帖是否是相匹配的
- ...
注意：
1. 上面的功能是给0基础同学们的一些启发，不用像钻研高考题一样咬文嚼字；但是每个人心目中可以有自己的产品，你可以把问答平台做出你自己的特色，这些是指引，但不应该成为困住你思维的牢笼；
1. 在你遇到问题的时候，先尝试结合我们准备的资料和搜索引擎自己解决，如果实在不能解决，带着你的**探索过程**来提问；
1. 你需要完成产品前后端的设计与开发，产品应当解决上述问答场景的问题，完整的结果应该包括：前后端代码、API文档、简单的代码说明文档、演示视频（可选)。
