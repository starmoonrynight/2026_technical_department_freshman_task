# 校园失物招领系统

Go 标准库 HTTP 服务 + SQLite + 原生 HTML/CSS/JavaScript。前后端同源，不需要 Node 构建步骤。现有登录、帖子权限和状态流转保留。

## 运行时 AI 与开发 AI 不同

开发 AI 是协助/代写项目代码的 Codex；运行时 AI 是后端按授权调用的 DeepSeek。前者写出的普通图片上传、SQL、词表搜索等代码，并不会因此在运行时自动成为“智能识图”。

- 识图建议由运行时模型生成，用户检查后才能发布；地点、时间和归属不由 AI 确认。
- 自动初筛是本地词表与 SQL；图文精筛由 DeepSeek 完成。通知、去重、权限与状态复查是确定性程序逻辑。
- 模拟模型的“识别”和“匹配”是人工指定的测试数据，不可作为真实模型准确率或识图成功的证明。

## 运行

在项目目录执行：

Go 版本以 `go.mod` 为准（当前为 1.27.1）。Node 仅用于可选的 JavaScript 语法检查，不是启动前端的必要条件。

```sh
go run .
```

打开 <http://localhost:8080>。默认使用 `lostfound.db` 和 `uploads/`；停止服务按 Ctrl+C。修改前端文件后也要重启，因为静态资源通过 `go:embed` 编入程序。

第一次升级旧数据库时，会先通过 SQLite `VACUUM INTO` 生成一致性备份 `lostfound.db.backup-时间戳`，再执行事务迁移。旧帖子保留，默认不参与 AI；旧的无图找到帖仍可浏览，编辑时需要补图。升级前建议先停止旧服务，并另存一份数据库。

使用全新演示数据、不动原数据库：

```sh
APP_DB_PATH=demo.db APP_UPLOAD_DIR=demo-uploads APP_ADDR=:8081 go run .
```

演示结束后数据仍在上述目录，不会自动删除。

## 功能与使用顺序

1. 注册并登录。登录态使用 HttpOnly Cookie，前端不保存 token。
2. 发布找到帖或丢失帖。找到帖至少一张照片；丢失帖可以无图。每帖最多 3 张 JPEG/PNG，单张最多 5 MiB，原图最多 1600 万像素。
3. 推荐上传照片后勾选 AI 授权，点击“识图填表”，检查建议并手动补充地点、时间，再发布。AI 不能直接替你发布。
4. 可选填写联系方式。公开列表始终不返回联系方式，只有登录后的帖子详情能查看；这不是“仅匹配对象可见”。
5. 用搜索范围选择精确 / 常规 / 宽泛，同时筛选帖子类型与状态。
6. 授权 AI 的寻找中帖子会触发后台匹配。双方帖子均需授权；找到帖有图，丢失帖无图时会明确降低证据解释。结果只通知丢失帖发布者，多个候选分别提供入口。
7. 发布者可以编辑、删除，或按“寻找中 → 已取得联系 → 已完成”改变状态。AI 不会自动改变状态。

**隐私提醒：** 发布图片前自行遮挡姓名、学号、证件号码。重新编码会移除 EXIF 等元数据，但不会遮挡画面内的信息。帖子图片是公开内容，草稿图片仅上传者可访问。联系方式不发送给 AI；图片及物品描述等匹配信息在授权后会发送给模型供应商。

## DeepSeek 配置

没有 Key 时，识图接口返回明确的 503；普通发帖、图片、搜索正常运行。不会伪造识图和匹配结果。已授权的匹配任务留在数据库中，配置 Key 并重启后处理；过时、删除、撤销授权的帖子会跳过。

在自己的终端设置环境变量，不要把真实 Key 发到聊天或写进 Git：

```sh
export DEEPSEEK_API_KEY='在自己的终端填写真实Key'
export DEEPSEEK_MODEL='deepseek-flash'
go run .
```

接入的是 DeepSeek Chat Completions 的图片输入格式，图片以 base64 data URL 发送，默认 API 地址 `https://api.deepseek.com`。模型 ID 可以更换，需确认供应商实际开放图像能力。[官方视觉文档](https://api-docs.deepseek.com/guides/vision/)。为控制短任务的延迟，明确使用非思考模式，限制输出为 1200 token；空响应或无效 JSON 不作为成功结果。[模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

`.env.example` 仅是配置模板；**程序不会自动读取 .env**。如果采用 .env，请手动在终端加载并保持文件不被提交。

使用自己创建、可信的 .env 启动正式程序时：

```sh
set -a
source .env
set +a
go run .
```

`set -a` 使加载的变量传给子进程，`set +a` 关闭该选项。不要 source 来历不明的文件，因为 shell 会执行其中的指令。本次真实测试使用的是数据解析器，不是 source，且不会把 Key 输出到终端。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| APP_ADDR | :8080 | 监听地址 |
| APP_DB_PATH | lostfound.db | SQLite 文件 |
| APP_UPLOAD_DIR | uploads | 图片目录 |
| APP_COOKIE_SECURE | false | HTTPS 部署设为 true；本地 HTTP 不要设置 true |
| DEEPSEEK_API_KEY | 空 | 仅服务端使用 |
| DEEPSEEK_BASE_URL | https://api.deepseek.com | API 地址，默认要求 HTTPS |
| DEEPSEEK_MODEL | deepseek-flash | 模型 ID |
| AI_DAILY_CALL_LIMIT | 100 | 按 UTC 日期持久化的调用次数上限，包含失败调用 |
| AI_MATCH_CANDIDATES | 20 | 单个匹配任务最多比较的候选，最大 50 |

每个用户每小时最多上传 30 张图片、发布 30 条帖子、请求 20 个识图任务、触发 20 个自动匹配任务。识图优先处理，单 worker 限制并发；任务最多尝试 3 次，服务重启后可恢复。额度不足的任务等待下一个 UTC 日期。

## 搜索与匹配的边界

- 精确：包含原始关键词，不做同义扩展；不是要求整个字段完全相等。
- 常规：原词、空格拆词和本地同义词，例如“校园卡 / 学生卡 / 一卡通”。
- 宽泛：再扩大到预设相关类别，例如“校园卡”能找到“银行卡”；先按加权相关度排序，再按发布时间倒序。
- 这是可解释的本地关键词扩展，不是任意词的通用语义搜索。词表在 `search.go`；没有引入向量数据库，也不为每次搜索付 AI 费用。
- 自动匹配先按类别（没有类别时使用名称）做宽泛初筛，再发送双方图文给 AI。只比较相反类型、不同用户、寻找中且双方授权的帖子。
- 相关度 ≥ 0.8、模型判断可能、存在依据且没有明确冲突时发送消息。**分数不是统计概率，更不代表确认归属。** 阈值需要通过真实样本评估。
- 同一帖子对、同一版本的正负结果都缓存；同一版本的正向通知去重。编辑后会产生新版本，可重新分析。消息列出旧结果，但过时线索会标记不可用。
- 初筛候选有数量上限，因此不能保证每件失物都被找到。AI 供应商连接、真实模型质量与费用，需要配置 Key 后联调。
- 当前 8 张照片的真实测试中，出现了未确定品类、可能错误的鼠标标签、受光线影响的颜色冲突与无法从闭盖照片核验的匹配理由。见测试报告；用户必须确认识图建议，不能把模型理由当作已核验事实。

### 用户提供的 8 张图片

本地图片测试已实际读取 JPEG/PNG 原文件，通过 multipart 上传、重编码与草稿权限检查。人为设定的模拟模型还验证了 8 个识图任务、10 次候选对比与 3 条去重通知；这些数字**不是 DeepSeek 的识图/匹配结果**。

2026-10-07 已另外进行真实 DeepSeek 批次测试：8 次识图 + 6 次对比，共 14 个实际请求，临时库生成 2 条候选通知，3 组明显不同物品对照未通知；一组充电宝候选因颜色冲突与 0.72 分而未通知。8 个结构化识图响应不等于全部准确，报告保留错误标签、未确定品类和理由中的推断问题，没有宣称 100% 准确率。

```sh
CASE_IMAGE_DIR='/你的案例目录' go test -run '^TestProvidedCaseImagesLocalPipeline$' -v -count=1 -timeout=60s
```

真实模型测试必须显式开启，默认 `go test ./...` 不会发出付费请求。单批最多 8 次识图、6 组图文对比，不自动重试；使用临时数据库，输出独立结果文件，不覆盖旧报告：
